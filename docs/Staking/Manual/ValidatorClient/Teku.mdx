In the directory storing validator keys, for each Keystore file Teku requires a file having the same file name containing the corresponding password. For example, a file named `keystore-m_12221_3600_1_0_0-11222333.txt` contains the password for `keystore-m_12221_3600_1_0_0-11222333.json`

Teku uses the Keystore password to load validators automatically.

**To create password files:**

<ol>
  <li>To create a temporary text file storing your Keystore password, type:</li>

```bash
sudo nano $HOME/validators-password.txt
```

  <li>In the `validators-password.txt` file, type your Keystore password, then press `CTRL+X`, then press `Y`, and then press `ENTER` to save the file and exit nano.</li>

  <li>To verify the password, type:</li>

```bash
sudo cat $HOME/validators-password.txt
```

  <li>To create a password file for each validator, type:</li>

```bash
for f in $HOME/ethstaker-deposit-cli/validator_keys/keystore*.json;
do
  sudo cp $HOME/validators-password.txt $HOME/ethstaker-deposit-cli/validator_keys/$(basename $f .json).txt;
done
```

</ol>

Select a configuration for Teku. To increase modularity and redundancy, running a standalone validator configuration is recommended.

    The following procedure presumes that you created a standalone beacon node when [Installing a Teku Consensus Client](/Staking/Manual/ConsensusClient/Teku).

    **To install a Teku validator client:**

    <ol>

      <li>To create a user for the validator service, type:</li>

```bash
sudo adduser --system --no-create-home --group validator
```

      <li>To copy your validator keys to Teku, type:</li>

```bash
sudo mkdir -p /var/lib/teku_validator/validator_keys
sudo cp $HOME/ethstaker-deposit-cli/validator_keys/keystore* /var/lib/teku_validator/validator_keys
```

sudo chown -R validator:validator /var/lib/teku_validator

      <li>To configure automatic startup, create a systemd unit file named `validator.service`</li>

```bash
sudo nano /etc/systemd/system/validator.service
```

      <li>In the `validator.service` file, paste the following lines where `<NetworkName>` is the value `hoodi` if you are creating a node on Hoodi testnet, or `mainnet` if you are creating a node on Mainnet; and, `<FeeRecipientAddress>` is an Ethereum wallet address that you control, designated for receiving priority fees and maximal extractable value (MEV) rewards:</li>

```bash
[Unit]
Description=Teku Validator Client Service
Wants=network-online.target
After=network-online.target
Documentation=https://ethpillar.coincashew.io/

[Service]
Type=simple
User=validator
Group=validator
Restart=on-failure
RestartSec=3
KillSignal=SIGINT
TimeoutStopSec=900
ExecStart=/usr/local/bin/teku/bin/teku validator-client \
  --network=<NetworkName> \
  --data-path=/var/lib/teku_validator \
  --validator-keys=/var/lib/teku_validator/validator_keys:/var/lib/teku_validator/validator_keys \
  --beacon-node-api-endpoint=http://localhost:5052 \
  --validators-proposer-default-fee-recipient=<FeeRecipientAddress> \
  --validators-graffiti="🏠🥩🛡️" \
  --metrics-enabled=true \
  --metrics-port=8009

[Install]
WantedBy=multi-user.target
```

For example, when running two validators, logs include entries similar to the following:

```bash
INFO  - Loading 2 validator keys...
INFO  - Loaded 2 Validators: 95d3986, 82b225f
```

When a Teku validator has synchronized and proceeded through the activation queue, logs include `Validator *** Published attestation` entries. For example:

```bash
teku[65367]: 03:50:51.761 INFO  - Validator cc1f3ade status is active_ongoing.
teku[65367]: 03:50:52.203 INFO  - Validator   *** Published attestation        Count: 1, Slot: 31362, Root: 90FC0DF4D5958E469134A015203B53B3FB94A0FC1038FB2462882906D4A729A2
```

**To clean up validator keys:**

<ol>

  <li>To delete the temporary text file storing your Keystore password, type:</li>

```bash
sudo rm $HOME/validators-password.txt
```

  <li>Confirm that you have backed up the `$HOME/ethstaker-deposit-cli/validator_keys` directory on the computer where you are creating a staking node, including the Keystore and Deposit Data files.</li>

  <table class="box">
    <tbody>
      <tr>
        <td class="boxLabel"><p class="boxLabel">Important<br /><img src={useBaseUrl('img/BoxImportant.png')} alt="Important" /></p></td>
        <td class="boxText"><p class="boxText">Having backup copies of the `validator_keys` directory on a USB stick simplifies recovering from issues on the staking node. If needed, you can always regenerate validator keys using the 24-word mnemonic seed.</p></td>
      </tr>
    </tbody>
  </table>

  <li>On the computer where you are creating a staking node, type the following command to remove the `validator_keys` directory:</li>

```bash
sudo rm -r $HOME/ethstaker-deposit-cli/validator_keys
```

</ol>
