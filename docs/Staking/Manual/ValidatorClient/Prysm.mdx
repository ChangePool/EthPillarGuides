**To install a Prysm validator client:**

<ol>
  <li>To create a user for the validator service and create a data directory, type:</li>

```bash
sudo adduser --system --no-create-home --group validator
sudo mkdir -p /var/lib/prysm/validators
```

  <li>To create a text file storing a password that Prysm uses to load validators automatically, type:</li>

```bash
sudo nano /var/lib/prysm/validators/password.txt
```

  <li>In the `password.txt` file, type your Keystore password, then press `CTRL+X`, then press `Y`, and then press `ENTER` to save the file and exit nano.</li>

  <li>To verify the password, type:</li>

```bash
sudo cat /var/lib/prysm/validators/password.txt
```

  <li>To import validator keys using the Keystore file, type the following command where `<NetworkName>` is the value `hoodi` if you are creating a node on Hoodi testnet, or `mainnet` if you are creating a node on Mainnet:</li>

```bash
sudo /usr/local/bin/validator accounts import \
  --accept-terms-of-use \
  --<NetworkName> \
  --wallet-dir=/var/lib/prysm/validators \
  --keys-dir=$HOME/ethstaker-deposit-cli/validator_keys
```

  <li>When prompted to create a new wallet password, type the Keystore password. When prompted for the imported accounts password, type the Keystore password again.</li>

  <li>To verify that the Keystore file imported successfully, type:</li>

```bash
sudo /usr/local/bin/validator accounts list \
  --wallet-dir=/var/lib/prysm/validators \
  --<NetworkName>
```

        <td class="boxText"><p class="boxText">If the Keystore file imported successfully, then the command displays the public key for each validator. For example:</p><CodeBlock language="bash">{KeysImportedFile}</CodeBlock></td>

  <li>To set ownership permissions and secure the folder where Prysm stores validator keys, type:</li>

```bash
sudo chown -R validator:validator /var/lib/prysm/validators
sudo chmod 700 /var/lib/prysm/validators
```

  <li>To configure automatic startup, create a systemd unit file named `validator.service`</li>

```bash
sudo nano /etc/systemd/system/validator.service
```

  <li>In the `validator.service` file, paste the following lines where `<NetworkName>` is the value `hoodi` if you are creating a node on Hoodi testnet, or `mainnet` if you are creating a node on Mainnet; and, `<FeeRecipientAddress>` is an Ethereum wallet address that you control, designated for receiving priority fees and maximal extractable value (MEV) rewards:</li>

```bash
[Unit]
Description=Prysm Validator Client Service
Wants=network-online.target
After=network-online.target
Documentation=https://ethpillar.coincashew.io/

[Service]
Type=simple
User=validator
Group=validator
Restart=on-failure
RestartSec=3
KillSignal=SIGINT
TimeoutStopSec=900
ExecStart=/usr/local/bin/validator \
  --<NetworkName> \
  --accept-terms-of-use \
  --datadir=/var/lib/prysm/validators \
  --beacon-rpc-provider=localhost:4000 \
  --beacon-rpc-gateway-provider=localhost:5052 \
  --wallet-dir=/var/lib/prysm/validators \
  --wallet-password-file=/var/lib/prysm/validators/password.txt \
  --graffiti="🏠🥩🛡️" \
  --monitoring-port=8009 \
  --suggested-fee-recipient=<FeeRecipientAddress>

[Install]
WantedBy=multi-user.target
```

  <li>To save and exit nano, press `CTRL+X`, then press `Y`, and then press `ENTER`</li>

  <li>To enable the service to start automatically when the computer boots, type the following commands:</li>

```bash
sudo systemctl daemon-reload
sudo systemctl enable validator.service
```

  <li>To start the validator client and check the status, type:</li>


```bash
sudo systemctl start validator.service
sudo systemctl status validator.service
```

  <li>To display logs in order to confirm that a validator client is functioning correctly, type:</li>

```bash
sudo journalctl -fu validator.service | ccze
```

</ol>

For example, when running two validators, logs include entries similar to the following:

```bash
level=info msg="Validating for public key" prefix=validator publicKey=0x95d39860a0d6
level=info msg="Validating for public key" prefix=validator publicKey=0x82b225f66476
```

When a Prysm validator has synchronized and proceeded through the activation queue, logs include `INFO validator: Submitted new attestations` entries. For example:

```bash
[2022-11-21 1:21:21]  INFO validator: Submitted new attestations AggregatorIndices=[12412] AttesterIndices=[73613] BeaconBlockRoot=0xca3213f1a3 CommitteeIndex=12 Slot=12422 SourceEpoch=12318 SourceRoot=0xd9ddeza1289 TargetEpoch=121231 TargetRoot=0xff313419acaa1
```

**To clean up validator keys:**

<ol>

  <li>Confirm that you have backed up the `$HOME/ethstaker-deposit-cli/validator_keys` directory on the computer where you are creating a staking node, including the Keystore and Deposit Data files.</li>

  <table class="box">
    <tbody>
      <tr>
        <td class="boxLabel"><p class="boxLabel">Important<br /><img src={useBaseUrl('img/BoxImportant.png')} alt="Important" /></p></td>
        <td class="boxText"><p class="boxText">Having backup copies of the `validator_keys` directory on a USB stick simplifies recovering from issues on the staking node. If needed, you can always regenerate validator keys using the 24-word mnemonic seed.</p></td>
      </tr>
    </tbody>
  </table>

  <li>On the computer where you are creating a staking node, type the following command to remove the `validator_keys` directory:</li>

```bash
sudo rm -r $HOME/ethstaker-deposit-cli/validator_keys
```

</ol>
